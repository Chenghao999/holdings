## 一、项目定位与核心目标

`holdings` 是一款专为 Python 开发者设计的本地化投资管理命令行工具，旨在解决支付宝、券商APP数据分散、历史回溯困难的问题。

- **当前阶段（MVP）**：纯命令行交互，支持手动导入+自动同步价格，数据全量本地存储（SQLite）。  
  **【修改】新增**：完整支持**交易手续费（佣金、印花税等）**和**基金托管费、管理费**的记录与成本核算，满足基金定投等场景的真实费用追踪。
- **中期规划**：升级为 **Textual TUI**（终端仪表盘）或 **Streamlit Web看板**。
- **远期规划**：基于 **PySide6** 打造跨平台桌面应用，或通过 **FastAPI** 提供RESTful服务。

## 四、数据库设计（扩展版）

> 在原有3张表基础上，新增 **`price_cache`** 表，并扩展 `transactions` 字段以支持多账户及费用记录。  
> **【修改】明确支持手续费、基金托管费等各类费用。**

```sql
-- 1. 交易记录表（支持多账户/组合，且包含费用字段）
CREATE TABLE transactions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    portfolio_group TEXT DEFAULT '默认',   -- 未来GUI支持多账户（如：养老金、压岁钱）
    symbol TEXT NOT NULL,
    market TEXT NOT NULL,                 -- 'A股' / '美股' / '黄金'
    asset_type TEXT NOT NULL,             -- 'stock' / 'etf' / 'gold'
    trade_date TEXT NOT NULL,
    trade_type TEXT NOT NULL,             -- 'BUY' / 'SELL' / 'FEE'  【修改】新增FEE类型
    quantity REAL NOT NULL,               -- 对于FEE类型，quantity填0
    price REAL NOT NULL,                  -- 对于FEE类型，price填0
    fee REAL DEFAULT 0,                   -- 【修改】统一费用字段（佣金、印花税、托管费等）
    notes TEXT
);

-- 2. 每日快照表（净值曲线数据源）
CREATE TABLE snapshots (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    snapshot_date TEXT NOT NULL UNIQUE,
    total_value REAL NOT NULL,
    cash_balance REAL DEFAULT 0,
    equity_value REAL NOT NULL,
    gold_value REAL NOT NULL,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
);

-- 3. 资产基础信息表（名称缓存）
CREATE TABLE asset_meta (
    symbol TEXT PRIMARY KEY,
    name TEXT,
    market TEXT,
    currency TEXT DEFAULT 'CNY',
    annual_management_fee REAL DEFAULT 0,  -- 【修改】新增年化管理费率（如基金托管费），用于参考
    updated_at TEXT
);

-- 4. 价格缓存表
CREATE TABLE price_cache (
    symbol TEXT PRIMARY KEY,
    price REAL NOT NULL,
    currency TEXT DEFAULT 'CNY',
    update_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    source TEXT                           -- 'akshare' / 'yfinance'
);

-- 索引优化
CREATE INDEX idx_trans_symbol ON transactions(symbol);
CREATE INDEX idx_trans_date ON transactions(trade_date);
CREATE INDEX idx_cache_time ON price_cache(update_time);
```

## 五、核心业务逻辑算法详解

| 模块 | 核心算法 / 实现细节 |
|------|-------------------|
| **持仓成本计算** | 采用**移动加权平均法**，**【修改】在买入时计入`fee`字段**：<br>• 买入时：`新成本 = (旧数量×旧成本 + 新数量×新价 + 新费用) / (旧数量 + 新数量)`<br>• 卖出时：**数量减少，成本价保持不变**（简单且符合国内多数券商展示逻辑）<br>• `trade_type='FEE'` 的交易**不改变持仓数量和成本**，仅影响现金余额，在报表中单独列示费用支出。<br>• 该逻辑封装在 `portfolio/calculator.py` 中，**纯函数无状态**。 |
| **盈亏与收益率** | • 持仓盈亏 = `(当前市价 - 平均成本) × 持仓数量 - 累计费用`（费用作为成本的一部分）<br>• 持仓收益率 = `(当前市价 / 平均成本 - 1) × 100%`（费用隐含在成本中） |
| **数据同步与容错** | • **三级降级策略**：A股优先 `akshare` → 超时重试1次 → 降级至 `yfinance`（仅支持部分A股大盘）<br>• **防封禁缓存**：同一代码在 `price_cache` 中若更新时间 < 5分钟，直接返回缓存，不请求网络。<br>• **进度反馈**：CLI使用 `tqdm` 或 `rich.progress`；未来GUI通过信号槽（Signal/Slot）更新进度条。 |
| **净值与回撤** | • 净值曲线：读取 `snapshots` 表，使用 `plotly` 绘制。<br>• 最大回撤：`(峰顶值 - 谷底值) / 峰顶值`，利用 `numpy` 向量化计算，无需循环。 |

## 六、CLI 命令设计（第一版用户体验）

```bash
# 初始化项目（创建数据库、config.yaml）
holdings init

# 添加一笔交易（支持交互式输入或全参数传入）
# 【修改】增加 --fee 参数，用于记录手续费、托管费等
holdings add --symbol 600519 --market A股 --type BUY --qty 100 --price 1680.5 --fee 5.0

# 添加一笔基金托管费用（trade_type=FEE）
holdings add --symbol 518880 --market A股 --type FEE --qty 0 --price 0 --fee 12.5 --notes "4月托管费"

# 查看当前持仓明细（支持按盈亏率排序）
holdings list --sort 盈亏率

# 从支付宝/券商导出的CSV批量导入历史交易（支持费用列映射）
# 【修改】import 命令支持 --fee-column 指定费用列，映射到 fee 字段
holdings import --file trades.csv --group 养老金 --fee-column 手续费

# 拉取所有资产的最新价格（更新price_cache和市值）
holdings sync --market 全部     # 也可指定 A股 / 美股 / 黄金

# 生成综合报表（终端显示表格+配比柱状图，费用支出单独汇总）
holdings report --verbose

# 记录当前时间点的总资产快照（用于净值追踪）
holdings snapshot --note "月度定投第12期"

# 生成交互式净值曲线图（自动打开浏览器预览HTML）
holdings chart --output networth.html --start 2025-01-01

# 删除指定ID的交易记录（需二次确认）
holdings remove --id 3
```

## 七、面向未来的 GUI 扩展策略（核心原则）

### 1. 写 CLI 时必须遵守的 3 条铁律
- **铁律一**：`portfolio/`、`data/`、`storage/` 目录下**严禁出现** `print`、`click.echo` 或 `rich.print`，所有返回必须是 `dict`、`DataFrame` 或 `Pydantic`/`dataclass` 对象。
- **铁律二**：配置管理必须支持 **读/写**（`config.save()`），因为GUI设置界面需要修改配置并持久化。
- **铁律三**：数据获取层（`data/fetcher.py`）同时提供 **同步方法**（供CLI）和 **异步方法**（供GUI协程），初期同步方法可直接调用 `asyncio.run()` 垫片。
