# 用户手册（CLI 命令大全 / USER_GUIDE）

> 面向普通用户的命令使用说明。所有命令均支持 `--help` 查看完整选项。

## 环境准备

```bash
# 通过 uv 或 poetry 安装
uv sync --all-extras

# 首次使用前初始化（创建数据库与 config.yaml）
holdings init
```

初始化后会在项目目录生成 `data/holdings.db` 与 `config.yaml`。

> 数据源依赖（akshare / yfinance）不在默认安装里。同步价格前请先
> `pip install 'holdings-cli[data]'`，或用 `holdings check` 确认是否齐全。

## 命令详解

### 1. `holdings init`

初始化项目：创建数据库表与默认配置文件。

```bash
holdings init
```

---

### 2. `holdings add` —— 新增交易

所有字段通过命令行参数传入，**没有交互式输入**。

```bash
# 买入股票（含手续费）
holdings add --symbol 600519 --market A股 --type BUY --qty 100 --price 1680.5 --fee 5.0

# 买入黄金ETF
holdings add --symbol 518880 --market A股 --type BUY --qty 1000 --price 4.85

# 卖出
holdings add --symbol 600519 --market A股 --type SELL --qty 50 --price 1750.0

# 记录一笔基金托管费（trade_type=FEE）
holdings add --symbol 518880 --market A股 --type FEE --qty 0 --price 0 --fee 12.5 --notes "4月托管费"

# 现金分红：公告「每 10 股派 5 元」→ 单价填每股 0.5
holdings add --symbol 600519 --market A股 --type DIVIDEND --qty 1000 --price 0.5 --date 2026-07-15

# 十送十：--qty 填**新增**的 1000 股，单价必须是 0
holdings add --symbol 600519 --market A股 --type BONUS_SHARE --qty 1000 --price 0 --date 2026-07-16

# 补录往日交易
holdings add --symbol 600519 --market A股 --type BUY --qty 100 --price 1600 --date 2025-03-01
```

| 参数 | 说明 |
|------|------|
| `--symbol` | 标的代码（必填） |
| `--market` | 市场（必填）：`A股` / `美股` / `黄金` |
| `--type` | 类型（必填）：`BUY` / `SELL` / `FEE` / `DIVIDEND` / `BONUS_SHARE` |
| `--qty` | 数量（必填；FEE 填 0；DIVIDEND 填持股数；BONUS_SHARE 填新增股数） |
| `--price` | 单价（必填；FEE 填 0；DIVIDEND 填每股派息；BONUS_SHARE 填 0） |
| `--fee` | 费用（佣金、印花税、托管费等），默认 0 |
| `--date` | 交易日期 `YYYY-MM-DD`，默认今天 |
| `--group` | 组合分组，默认取配置项 `default_group` |
| `--notes` | 备注（可选） |

写入前会结合**历史持仓**校验这笔交易：卖出数量不得超过当时的持有量，数量、单价、费用不得为负。
补录往日交易也按交易发生时的持仓判定，不按当前持仓。校验失败返回退出码 `5`，账本不会写入。

**公司行为改的是成本价，不是「一笔收益」。** 分红按 `持股数 × 每股派息` 摊薄持仓成本
（与券商 APP 上看到的成本价一致），送股 / 转增 / 拆股则是总成本不变、股数增加。
好处是报表的「总盈亏」里自然含分红，不用另开一列去加。代价是**成本价从此不再等于
「你花的钱」**——它被分红改过。两类都要求账本上此刻有持仓，所以日期要记在持仓期间。

> 长期持有、分红累计到把成本价摊成 0 甚至负数，是真实会发生的（券商 APP 也这么显示）。
> 成本价照实显示，但**盈亏率会显示 `—`**：分母不为正时那个百分比没有意义，
> 印一个出来只会是符号反了的怪数。

### 3. `holdings list` —— 查看持仓

```bash
# 查看全部持仓
holdings list

# 按盈亏率降序
holdings list --sort 盈亏率

# 只看某个组合
holdings list --group 养老金
```

`--sort` 接受表格里的中文表头（`代码` / `名称` / `市场` / `类型` / `数量` / `成本价` /
`现价` / `市值` / `累计费用` / `盈亏` / `盈亏率`），一律降序；也接受对应的英文列名（如 `profit_rate`）。
传其它值会直接报错，不会静默按原顺序输出。没有行情的标的排在末尾，不会混进排序结果。

**终端窄于 100 列时自动改用简表。** 持仓表有 11 列，在 80 列终端里放不下，
Rich 会平均截断每一列，代码列只剩 `6005…`——认不出持的是什么。所以窄终端下
只显示四列，宽终端（≥ 100 列）显示全部十列：

```text
# 窄终端（80 列）
┌────────┬───────────┬───────────┬─────────┐
│ 代码   │ 数量       │ 现价       │ 盈亏率  │
├────────┼───────────┼───────────┼─────────┤
│ 600519 │  100.0000 │ 1750.0000 │   4.13% │
└────────┴───────────┴───────────┴─────────┘
```

**没同步过时看到的是 `—`，不是亏损。** 还没执行过 `holdings sync` 的标的没有行情，
市值、盈亏、盈亏率一律显示 `—`（现价本来就取不到，同样是 `—`），并在表尾给出提示：

```text
总市值 200.00 | 总成本 100.00 | 总盈亏 100.00 (100.00%) | 累计费用 0.00
1 个标的无行情（成本合计 200.00），未计入上面的汇总；请先执行 holdings sync
```

**外币计价的标的不与人民币混加。** 持有美股（美元报价）与 A 股（人民币报价）时，
汇总只按人民币相加，美元标的的市值、成本、盈亏都不计进去，并在表尾说明：

```text
总市值 1,200.00 | 总成本 1,000.00 | 总盈亏 200.00 (20.00%) | 累计费用 0.00
1 个标的以美元计价（成本合计 1,000.00），未计入上面的汇总；本工具按人民币口径汇总，不做汇率换算
```

行内同理：**账本事实照常显示**（数量、成本价、累计费用），**行情推出来的数字显示 `—`**
（市值、盈亏、盈亏率）——那三个数只有和人民币放在一起才有意义，而它们放不到一起。
现价照常显示，但会带上币种（`200.0000 USD`）：同一列里混着两种货币而不加标注，
用户看到的仍是一个没有单位的数。本工具**不做汇率换算**，要人民币口径的总额，
得自己换算成本币再录入。

汇总的口径是**能按人民币计价的标的**，即「有行情」且「行情是人民币」两者都满足：
没行情的市值算不出来，让它以 0 参与汇总就会把「不知道」印成「血亏 100%」。
没被计入的部分由提示行说明数量与成本合计——两条提示语分别对应两种原因，
要去 sync 的只有前者。

### 4. `holdings group` —— 管理组合

组合是交易上的一个标签：`add --group` / `import` 落到它上面，`list --group` 按它筛。
但列表里只会出现**已经有交易的**组合——`config.yaml` 的 `default_group` 若还没被
用过，它不会出现在这里。

```bash
# 列出全部组合，以及各自的总市值 / 成本 / 盈亏
holdings group list

# 改名：把「默认」的全部交易改到「主账户」
holdings group rename 默认 主账户

# 合并：「打新」并入「主账户」，「打新」之后不再存在
holdings group merge 打新 主账户
```

```text
                                 组合概览
┏━━━━━━━━┳━━━━━━━━┳━━━━━━━━━━━━┳━━━━━━━━━━━━┳━━━━━━━━━━━┳━━━━━━━━┳━━━━━━━━┓
┃ 组合   ┃ 标的数 ┃     总市值 ┃     总成本 ┃      盈亏 ┃ 盈亏率 ┃ 未计入 ┃
┡━━━━━━━━╇━━━━━━━━╇━━━━━━━━━━━━╇━━━━━━━━━━━━╇━━━━━━━━━━━╇━━━━━━━━╇━━━━━━━━┩
│ 主账户 │      2 │ 167,000.00 │ 156,000.00 │ 11,000.00 │  7.05% │        │
│ 打新   │      1 │   1,400.00 │   1,200.00 │    200.00 │ 16.67% │        │
└────────┴────────┴────────────┴────────────┴───────────┴────────┴────────┘
```

没同步过行情时，总市值 / 盈亏那几列是 `—`，「未计入」列会写明有几个标的没算进来：

```text
┏━━━━━━━━┳━━━━━━━━┳━━━━━━━━┳━━━━━━━━┳━━━━━━┳━━━━━━━━┳━━━━━━━━━━┓
┃ 组合   ┃ 标的数 ┃ 总市值 ┃ 总成本 ┃ 盈亏 ┃ 盈亏率 ┃ 未计入   ┃
┡━━━━━━━━╇━━━━━━━━╇━━━━━━━━╇━━━━━━━━╇━━━━━━╇━━━━━━━━╇━━━━━━━━━━┩
│ 主账户 │      2 │      — │      — │    — │      — │ 2 无行情 │
└────────┴────────┴────────┴────────┴──────┴────────┴──────────┘
组合『主账户』：2 个标的无行情（成本合计 156,000.00），未计入上面的汇总；请先执行 holdings sync
```

每一行的数与 `holdings list --group <名字>` 底下那行汇总**同源**——口径只有一处实现，
不会两家各算一份。「未计入」列写明这一行里有多少标的没算进汇总（没行情 / 外币计价），
没有就留白；有内容时表后还会跟一句该组合的提示，句子与前两节那份是同一处来的。

**不印总额。** 每行都排除了自己那部分没计进来的标的，把它们加起来得到的数既不是
全体也不是部分——那会是一个看着像结论的错数。

改名与合并只动历史数据的 `portfolio_group` 字段，一次事务写完。两点要留意：

- **改名撞上已有的名字会报错**，不静默合并——那会让「改名」这条命令的语义比名字大。
  报错信息里会给出该用的那条 `group merge`。
- **合并不可逆**：改名能改回来，合并后拆不回去。先跑一次
  `holdings export --what ledger --out ledger.csv` 留一份账本，就是后悔药。

改的若正好是 `config.yaml` 里 `default_group` 指定的那个组合，命令照做，但会补一句提醒：
之后 `holdings add` 不带 `--group` 时还会写到那个名字上，账本会因此多出一个组合。
要把默认落到别处，改 `config.yaml` 的 `default_group`（见 [CONFIG_SPEC](CONFIG_SPEC.md)）。

退出码：组合不存在 → `2`；名字为空、改名撞名、合并时源与目标相同 → `5`。

### 5. `holdings meta` —— 维护标的的基础信息

```bash
# 记下名称与年化管理费率（如基金托管费）
holdings meta --symbol 518880 --name "黄金ETF" --fee-rate 0.5

# 看这个标的现在记了什么
holdings meta --symbol 518880

# 删掉
holdings meta --symbol 518880 --remove
```

| 参数 | 说明 |
|------|------|
| `--symbol` | 标的代码（必填） |
| `--name` | 名称，`holdings list` 的名称列取自这里 |
| `--currency` | 币种，默认 `CNY` |
| `--fee-rate` | 年化管理费率（%），**仅作参考展示** |
| `--remove` | 删除该标的的基础信息 |

一个字段都不给时是**查看**当前记录，不会写一条空记录把已有内容清掉。
重复 `--symbol` 是覆盖：没给的字段保留原值。

> ⚠️ **年化管理费率不参与成本计算。** 它只是「你填的费率加起来是多少」，
> 真实费用仍要靠 `holdings add --fee` 逐笔记录。本工具**不会**按持仓天数
> 自动计提管理费——那会让成本价随日历漂移，与移动加权平均成本法冲突。

`AssetType` 的 `etf` 目前没有单独的录入入口，黄金 ETF 用 `--market A股` 记即可。

### 6. `holdings import` —— 对账单批量导入

从券商 / 支付宝导出的对账单批量导入历史交易。

```bash
holdings import --file trades.csv --group 养老金 --fee-column 手续费
```

| 参数 | 说明 |
|------|------|
| `--file` | 对账单文件路径 |
| `--group` | 组合分组；对账单里有资金账号时以账号为准，它只接住没有账号的行（见「[一个文件里的多个组合](#一个文件里的多个组合)」） |
| `--broker` | 对账单格式名（见下表）；不给则按表头自动识别 |
| `--fee-column` | 文件里的费用列名，覆盖该格式自带的费用列 |
| `--strict` | 有未入账的行时一笔都不写，并以退出码 5 结束 |
| `--dedupe` | 重复行怎么办：`error`（默认，报错、一笔不写）/ `skip` / `off`，见「[同一个文件导两遍](#同一个文件导两遍)」 |

导入是**整批校验、单事务写入**：任一行数据非法（或缺少必需列、`--fee-column`
指向不存在的列）则一笔都不写入，并提示出错行号。不会留下半批数据。

#### 支持哪些格式

`--broker` 指定格式名；不给就**按表头自动识别**：

| `--broker` | 格式 | 表头长什么样 |
|-----------|------|-------------|
| `csv` | 标准 CSV（本文档用的那种） | 英文列名 `symbol` / `trade_date` / `trade_type` / … |
| `demo-a` | 示例格式 A | `证券代码` / `成交日期` / `业务名称`；费用拆成 `佣金` + `印花税` + `过户费` 三列 |
| `demo-b` | 示例格式 B | `股票代码` / `发生日期` / `业务标志`；费用一列 `手续费` |

> `demo-a` / `demo-b` 是**演示用的夹具，不是真实券商**。真实对账单各家差别很大，
> 对着想象的格式写映射等于闭着眼猜，所以真实券商的解析器等真实样本
> （BACKLOG B-30）。要接自己的券商：照 `src/holdings/data/brokers/demo_a.py`
> 加一个模块、在 `BROKERS` 里加一行即可，命令行的代码一行都不用改。

**编码不用先转**：UTF-8（含 BOM）、GB18030 / GBK、UTF-16 都直接读。
Windows 上 Excel「另存为 CSV」出来的就是 GBK。

**认不出就不猜**：表头对不上任何格式时报「认不出这份对账单的格式，请用
`--broker` 指定」并列出可选项，**一笔都不写**；同时像两家时同样报错。
每次导入都会印一行「解析格式：…」，告诉你它认成了哪家——认错了才有得查。

#### 哪些行会入账

`trade_type` 列认这些值：

| 取值 | 含义 | `quantity` | `price` |
|------|------|-----------|---------|
| `BUY` | 买入，费用摊入持仓成本 | 成交数量 | 成交单价 |
| `SELL` | 卖出，数量减少、成本价不变 | 成交数量 | 成交单价 |
| `FEE` | 独立费用记录，不改变数量与成本 | 0 | 0 |
| `DIVIDEND` | 现金分红，摊薄持仓成本 | **持股数** | **每股派息** |
| `BONUS_SHARE` | 送股 / 转增 / 拆股，股数增加、成本价摊薄 | **新增股数** | 必须为 0 |

中文写法也认：`分红`、`股息`、`红利入账`、`派息` 都会归到 `DIVIDEND`；
`送股`、`转增`、`送转股`、`送股转增`、`拆股`、`拆分` 归到 `BONUS_SHARE`。

> **公告写「每 10 股派 5 元」，`price` 要填 0.5**（每股派息），不是 5。
> 这样每一行的金额都正好是 `quantity × price`，与买入同构。

#### 哪些行不会入账

一份真实的对账单里还有配股、银证转账、利息这类行，以及**没给对数字**的公司行为行。
**它们不入账，但会被逐行报出来**，不会静默跳过：

```text
解析格式：标准 CSV
识别 5 行，入账 1 笔，未入账 4 行，重复 0 行
  第 3 行 分红派息（分红），未入账：对账单这一行没有给出持股数与每股派息，补上才能入账
  第 4 行 配股，未入账：配股缴款的口径尚未支持（见 BACKLOG B-38）；可拆成一笔 BUY 手工补录
  第 5 行 银证转账，未入账：银证转账动的是现金，不影响持仓
  第 6 行 利息，未入账：利息不计入持仓成本
```

| 类别 | 常见写法（写到 `trade_type` 列里） | 为什么不入账 |
|------|-----------------------------------|-------------|
| 分红派息 | `分红`、`股息`、`红利入账`、`派息` | **支持了**，但这一行缺持股数或每股派息，或填了 0 |
| 送股转增 | `送股`、`转增`、`送转股` | **支持了**，但这一行缺新增股数，或单价填了非 0 |
| 配股 | `配股`、`配股缴款` | 缴款与配售比例的口径尚未支持（BACKLOG B-38） |
| 银证转账 | `银行转证券`、`证券转银行` | 动的是现金，不影响持仓 |
| 利息 | `利息`、`利息归本`、`结息` | 不计入持仓成本 |

前两类与后三类的区别很实际：**它们只是这一行没写对，修好文件就能导进来**；
后三类要等新版本，配股可以先拆成一笔 `BUY` 手工补录。

公司行为行的数量、价格**留空**是正常的：对账单里这几行常常只有金额、没有股数，
而金额所在的那一列各家叫法不同。工具宁可报出「这一行没有给出持股数与每股派息」，
也不静默算一笔 0 元分红给你，更不会因为这一行就让整份对账单导不进来。

汇总行固定为 **识别 / 入账 / 未入账**，查重时多一截 **重复**，落了多个组合时多一截
**落组**，有列退回默认值时多一截 **标的资料**（见下）。`0` 也照印——「0」是被数出来
的，不是没数。

`--strict` 给脚本用：有未入账的行时**一笔都不写**、退出码 `5`（默认是 `0`）。

> `trade_type` 里出现**认不出**的值（既不是上表里的，也不在这张表里）仍然是
> 整批拒绝、退出码 `5`、一笔都不写。那与「认识但不入账」是两回事：
> 前者要你改文件，后者只要你知情。

#### 一个文件里的多个组合

同一份对账单常常覆盖多个资金账号（普通账户、信用账户、养老金账户……）。
对账单里有账号列时，**每一行按它自己的账号落成组合分组**，一个文件导进来就是
多个组合，不必拆成多份文件分几次导：

```text
解析格式：示例格式 A
识别 3 行，入账 3 笔，未入账 0 行，重复 0 行
落组：A12345 2 笔、B67890 1 笔
```

| 格式 | 账号列 |
|------|--------|
| 标准 CSV | `account` |
| `demo-a` | `资金账号` |
| `demo-b` | `股东账号` |

**账号优先，`--group` 只接住没有账号的行。** 文件说得很清楚每一行属于哪个账号，
命令行的参数说不了这么细；反过来让 `--group` 压过账号，一份两账号的对账单会被
悄悄并成一个组，而你在汇总里看不出来。所以：给了账号的行按账号走，没给账号的
行才落到 `--group`（或配置项 `default_group`）。文件里没有账号列时，行为与从前
一样——整份进同一个组。

**账号不需要事先建**：组合是交易记录上的一个字段，不是一张需要注册的表。导入后
直接 `holdings list --group A12345` 就能筛出来。

`落组` 那一截**只在真有多个组时才印**：一个组是常态，每次都印就成了废话；而一
旦账号让账分散到几个组，你需要当场知道——否则按默认分组去看会以为这笔导入丢了。

#### 只有代码的对账单

券商导出的 CSV 常常只有代码，没有市场列、也没有资产类型列。这两列空着时，本工具
**按代码去数据源问一次**，把能补的补上：

```text
解析格式：标准 CSV
识别 1 行，入账 1 笔，未入账 0 行，重复 0 行
标的资料：全部取自对账单或数据源
```

- **文件里写了的列以文件为准**，数据源不会覆盖它。那份资料照样查一次，是为了把
  **名称**落进 `asset_meta`——`holdings list` 的名称列取自那里。
- 先问哪个市场**按代码形状排**（6 位数字先问 A 股，其它先问美股），这只是为了少发
  一半无谓请求；**落库的市场是数据源说的**，不是形状猜的。第一个市场说「没这个
  标的」时会接着问下一个。
- **取不到不是错误**：离线、查无此码都照常导入，补不上的列退回默认值（市场 `A股`、
  资产类型 `stock`），但**逐列报出是哪些行**——不说明就等于把默认值当成了事实：

```text
标的资料：2 行有列按默认值记
  第 2 行市场没取到，按默认值记：A股
  第 3 行资产类型没取到，按默认值记：stock
  对不上的可用 holdings meta 改
```

  报的是**哪一列**没问到，不是「整行没取到」：市场查到了而资产类型没查到是常事
  （不是每个源都分得出股票与 ETF）。
- 查资料会联网、也会写 `asset_meta` 缓存，所以它发生在**校验与查重都通过之后**：
  一次中止的导入不发请求、也不留缓存。查到的资料默认缓存 1 天
  （配置项 `data_sources.instrument_ttl_seconds`）。

> 黄金是个例外：`GC=F` 这类合约没有取资料的源，得靠对账单自带的市场列，或事后
> `holdings meta` 补。国内黄金 ETF（如 `518880`）走的是 A 股那条链路，问得到。

#### 同一个文件导两遍

对账单是**逐月补充导出**的，本月那份里含上月最后几笔——重复导入是必然撞上的，
不是操作失误。所以 `import` 会先查重：发现有已经记过的行，**默认报错、一笔不写**。

```text
解析格式：示例格式 A
  第 2 行重复：与库里已有的 #1 是同一笔——600519 2025-01-02 BUY 100 @ 1500
错误（5）：1 行与已有记录重复（第 2 行），未写入任何数据；
确认不是同一笔就加 --dedupe off，要跳过重复行就加 --dedupe skip
```

| `--dedupe` | 行为 | 什么时候用 |
|-----------|------|-----------|
| `error`（默认） | 报出重复的行号，一笔不写，退出码 `5` | 想先看清楚重复了什么 |
| `skip` | 跳过重复的行，其余照常写入 | 逐月补充导出，重叠是已知的 |
| `off` | 不查重，原样全写 | 确实是两笔不同的成交，见下 |

判重看两样东西：对账单里有**券商流水号**（标准 CSV 的 `external_id` 列）就按
它判，那是券商给的唯一标识；没有则退回**全字段指纹**——标的 + 日期 + 类型 +
数量 + 价格 + 费用，六项全同才算重复。

> **指纹认不出的那一种情况，`--dedupe off` 就是为它留的。** 同一天分两次、
> 同价同费各买 100 股，是两笔真实成交，指纹分不开，会报成重复。工具不替你
> 决定要不要丢：默认报错让你看到，确认是两笔就 `--dedupe off` 放行。
> 反过来，默认也**不是**静默跳过——被跳过的那一笔可能正是你要的。

库里已有的记录也一样算，哪怕它是手录的（`holdings add`）——判重不看这笔是怎么
进来的。同一批文件内部重复的行同样会报出来。

反过来，导出的账本用的就是下面这一节认的那份表头，所以**导得出去也导得回来**
（见 [`holdings export`](#6-holdings-export--导出账本--持仓表--快照)）。

### 7. `holdings export` —— 导出账本 / 持仓表 / 快照

```bash
holdings export --out ledger.csv                       # 账本（默认）
holdings export --what holdings --out 持仓.csv          # 当前持仓表
holdings export --what snapshots --format json --out 快照.json
```

| 参数 | 说明 |
|------|------|
| `--what` | `ledger`（默认）/ `holdings` / `snapshots` |
| `--out` | 输出文件路径，**必填**（三样共用一个默认名会互相覆盖） |
| `--format` | `csv`（默认）/ `json` |

| `--what` | 导出什么 | 给谁用 |
|----------|---------|--------|
| `ledger` | 交易流水 | 备份 / 迁移，**能再导回来** |
| `holdings` | 当前持仓表 | 报税、拿去 Excel 里算 |
| `snapshots` | 资产快照 | 备份 |

#### 账本能导回去

账本用的是**标准 CSV 表头**，也就是 `holdings import` 认的那一份，所以换台机器
就是：

```bash
# 旧机器
holdings export --out ledger.csv
# 新机器
holdings init && holdings import --file ledger.csv
```

数量与金额**原样写出，不做四舍五入**——这是备份不是报表，把 `10.045` 写成
`10.05` 会让导回来的账本和原来不一样。组合分组（`portfolio_group`）跟着
`account` 那一列一起走，一份多账户的账本导回来还是多账户。

导出的 CSV **带 BOM**（`utf-8-sig`），Excel 双击打开中文不乱码；本工具自己的
导入第一个剥的就是 BOM，所以带 BOM 的账本照样导得回来。

**行情不在里面。** 现价 / 市值 / 盈亏来自 `price_cache`，那是能从数据源重取的
缓存，不是账本——导进新库后这几列是空的，`holdings sync` 一次就回来。备份要
备的是补不回来的东西。

**往返之后 `source` 会变成 `csv`。** 它记的是「这笔是从哪份对账单读进来的」，
而标准 CSV 表头里没有这一列。这是句实话：导回来的那一行确实是从标准 CSV
读进来的。

#### 报税那张表

`--what holdings` 导出的是 `holdings list` 那张表本身（列名用英文，与
`--sort` 接受的写法一致），**多一列 `currency`**：终端表格里不显示它（人民币
是默认口径），但少了它，一份含美股的持仓表就分不清哪一行的市值是美元。

算不出来的格子（没有行情的标的）在 CSV 里是**空单元格**，在 JSON 里是 `null`。
写成 `nan` 的话 Excel 里看着像个词，拿它求和得到的是「没有」而不是报错。

#### 空库也导得出

一个刚 `init` 完的库导出成功、文件里只有表头，并印一句
`已导出 0 行到 ledger.csv（库里还没有交易记录）`——「0 行」是被数出来的，
不是没导。

### 8. `holdings sync` —— 同步最新价格

```bash
holdings sync --market 全部     # 也可指定 A股 / 美股 / 黄金
```

同步会更新 `price_cache` 与持仓市值。同一标的 5 分钟内不会重复请求网络。

只要有一个标的同步成功即返回退出码 `0`；**全部失败返回 `1`**，便于脚本判断。

### 9. `holdings report` —— 生成综合报表

```bash
holdings report --verbose

# 只看一个组合（与 holdings list --group 同一套筛选）
holdings report --group 养老金

# 每个组合各出一块
holdings report --by-group
```

终端显示持仓表格、汇总行与绩效行；加 `--verbose` 额外显示费用分项表与资产配置占比表。

`--by-group` 按组合名升序，每个组合一块（持仓表 + 汇总行 + 该组合的口径提示），
`--verbose` 下费用分项与资产配置占比也按组合各出一份。**绩效一节仍是整份组合的**：
快照表不按组合记录，报表末尾会有一句说明——不然那行「整份组合的数」混在若干
「单个组合的数」中间，很容易被当成其中一组的口径。两个参数不能同时用（退出码 `5`）。

用 `holdings meta --fee-rate` 记过年化管理费率时，多印一行：

```text
年化管理费率合计 0.5%（仅供参考，未计入成本）
```

**它不在「累计费用」里**，也不影响成本价与盈亏——那行字就是为了避免被读成
「费用又多了这么多」。

绩效行取自 `snapshots` 表（与持仓汇总的交易流水是两条数据源），形如：

```text
绩效（4 条快照，2025-01-01 ~ 2025-04-01）：最大回撤 25.00% | 年化收益 47.23% | 夏普 0.94
```

**看到 `—` 不是出错，是这组快照算不出那个指标**，行尾会跟上原因：

| 指标 | 什么时候是 `—` |
|------|---------------|
| 最大回撤 | 快照少于 2 条（1 个点算出的「0.00%」不是结论） |
| 年化收益 | 首末快照跨度不足 30 天，或首条快照净值为 0 |
| 夏普 | 快照间隔不规律。夏普要乘一个年化系数，而该系数只在采样频率恒定时才有意义；快照由你手记，间隔忽长忽短（例如漏记了一周）时强行折算等于给一个错的数 |

间隔的判据是各段间隔的变异系数不超过 25%：月度快照的 28~31 天、每周快照的 7 天都在阈值内。

### 10. `holdings snapshot` —— 记录资产快照

```bash
holdings snapshot --total 158000 --equity 120000 --gold 20000 --cash 18000
```

| 参数 | 说明 |
|------|------|
| `--total` | 总资产（必填） |
| `--equity` | 权益类资产，默认 0 |
| `--gold` | 黄金资产，默认 0 |
| `--cash` | 现金余额，默认 0 |
| `--date` | 快照日期 `YYYY-MM-DD`，默认今天 |
| `--flow` | **上次快照之后**的净入金：入金为正、出金为负，默认 0。基准对比据此剔除现金流 |
| `--note` | 备注，写入数据库，可用 `holdings snapshots` 查看 |

同日期的快照只能有一条，重复记录会报错（退出码 `4`）。

> **`--flow` 什么时候填**：两次快照之间往证券账户里转过钱（银证转账）就填，
> 转进来是正数、转出去是负数。它是给 `holdings benchmark` 用的——不填的话，
> 那笔钱会被当成「你赚的」，跑赢 / 跑输就被高估了。**不填等于断言
> 「这段时间没有出入金」**，不是「还没记」。

### 11. `holdings snapshots` —— 查看已记录的快照

```bash
holdings snapshots
```

按日期升序列出全部快照：日期、总资产、权益 / 黄金 / 现金分项、净入金，以及备注。

```text
                                 资产快照
┌────────────┬────────────┬────────────┬──────────┬──────────┬────────────┬────────────────┐
│ 日期       │ 总资产      │ 权益        │ 黄金      │ 现金      │ 净入金      │ 备注            │
├────────────┼────────────┼────────────┼──────────┼──────────┼────────────┼────────────────┤
│ 2025-01-01 │ 158,000.00 │ 120,000.00 │ 20,000.00 │ 18,000.00 │            │ 月度定投第12期  │
│ 2025-02-01 │ 213,000.00 │ 170,000.00 │ 22,000.00 │ 21,000.00 │ +50,000.00 │ 追加投入        │
└────────────┴────────────┴────────────┴──────────┴──────────┴────────────┴────────────────┘
```

净入金为 0 时留白（`--flow` 不填就是 0），不是印一排 `0.00`。

没记过任何快照时会给出提示，而不是印一张空表。

> 与 `holdings snapshot`（单数）是一对：那个写，这个看。

### 12. `holdings chart` —— 生成净值曲线图

```bash
holdings chart --output networth.html
```

基于 `snapshots` 表生成交互式 HTML 并自动打开浏览器。

| 参数 | 说明 |
|------|------|
| `--output` | 输出 HTML 路径，默认 `networth.html` |
| `--start` | 起始日期 `YYYY-MM-DD`，只画该日（含）之后的点 |

```bash
# 只看 2025 年 3 月以来的净值
holdings chart --start 2025-03-01 --output 2025.html
```

**起始日期之后没有数据时会报错，而不是生成一张空图**——空图与「净值跌没了」
在图上是分不出来的。提示里会带上现有的数据范围，照着调 `--start` 即可：

```text
错误（2）：2030-01-01 之后没有快照（现有 4 条，2025-01-01 ~ 2025-04-01）；
请调整 --start 或先执行 holdings snapshot
```

还没记过任何快照时同理，提示会直接让你先执行 `holdings snapshot`。

### 15. `holdings web` —— 只读看板

```bash
pip install 'holdings-cli[web]'    # 需要 FastAPI，默认不装
holdings web
# 看板已起在 http://127.0.0.1:8420/
```

持仓 / 报表 / 净值曲线三页，数据与 CLI、TUI 完全同源（都来自 `services/`）。

| 页面 | 内容 |
|------|------|
| `/`（持仓） | 总市值 / 总成本 / 总盈亏 / 累计费用四张卡片 + 持仓表；没同步过的标的显示 `—` 并提示去 `sync`，外币标的按第 3 节的规则排除并提示 |
| `/report`（报表） | 绩效指标（最大回撤 / 年化 / 夏普）+ 资产配置占比 + 费用分项，即 `holdings report --verbose` 的那一份 |
| `/chart`（净值曲线） | 交互式净值曲线，可用起始日期筛；等同于 `holdings chart` 的图 |

holdings web --host 0.0.0.0 --port 9000    # 改监听地址与端口

> 净值曲线那一页从 CDN 取 plotly.js，看它需要联网；要一张能离线打开的图，
> 用 `holdings chart` 导出独立文件。

### 16. `holdings check` —— 检查运行环境

```bash
holdings check
holdings check --json
```

列出各依赖包是否已安装，标出缺失的必需依赖。全部齐全返回 `0`，
缺失必需依赖返回 `6`（缺少依赖是「装包」问题，与网络故障分开）。

> `--json` 模式的退出码与文本模式一致（缺必需依赖时 `6`），JSON 里也带
> `"ok"` 字段（缺必需依赖时为 `false`），管道消费时用哪个都行。

## 退出码

| 退出码 | 含义 |
|--------|------|
| `0` | 成功 |
| `1` | 网络错误 / 数据源不可用（可重试） |
| `2` | 数据不存在（标的 / 交易记录未找到） |
| `3` | 配置错误 |
| `4` | 数据库错误 |
| `5` | 参数校验失败 / 用户输入非法 |
| `6` | 缺少依赖（重试没有用，要装包） |
| `130` | 用户中止（`Ctrl-C` 或拒绝确认） |

错误信息一律输出到 `stderr`，格式为 `错误（<退出码>）：<人类可读信息>`。
完整规范见 [ERROR_HANDLING.md](ERROR_HANDLING.md)。
