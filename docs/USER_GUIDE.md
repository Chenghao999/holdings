# 用户手册（CLI 命令大全 / USER_GUIDE）

> 面向普通用户的命令使用说明。所有命令均支持 `--help` 查看完整选项。

## 环境准备

```bash
# 通过 uv 或 poetry 安装
uv sync --all-extras

# 首次使用前初始化（创建数据库与 config.yaml）
holdings init
```

初始化后会在项目目录生成 `data/holdings.db` 与 `config.yaml`。

> 数据源依赖（akshare / yfinance）不在默认安装里。同步价格前请先
> `pip install 'holdings[data]'`，或用 `holdings check` 确认是否齐全。

## 命令详解

### 1. `holdings init`

初始化项目：创建数据库表与默认配置文件。

```bash
holdings init
```

---

### 2. `holdings add` —— 新增交易

所有字段通过命令行参数传入，**没有交互式输入**。

```bash
# 买入股票（含手续费）
holdings add --symbol 600519 --market A股 --type BUY --qty 100 --price 1680.5 --fee 5.0

# 买入黄金ETF
holdings add --symbol 518880 --market A股 --type BUY --qty 1000 --price 4.85

# 卖出
holdings add --symbol 600519 --market A股 --type SELL --qty 50 --price 1750.0

# 记录一笔基金托管费（trade_type=FEE）
holdings add --symbol 518880 --market A股 --type FEE --qty 0 --price 0 --fee 12.5 --notes "4月托管费"

# 补录往日交易
holdings add --symbol 600519 --market A股 --type BUY --qty 100 --price 1600 --date 2025-03-01
```

| 参数 | 说明 |
|------|------|
| `--symbol` | 标的代码（必填） |
| `--market` | 市场（必填）：`A股` / `美股` / `黄金` |
| `--type` | 类型（必填）：`BUY` / `SELL` / `FEE` |
| `--qty` | 数量（必填；FEE 类型填 0） |
| `--price` | 单价（必填；FEE 类型填 0） |
| `--fee` | 费用（佣金、印花税、托管费等），默认 0 |
| `--date` | 交易日期 `YYYY-MM-DD`，默认今天 |
| `--group` | 组合分组，默认取配置项 `default_group` |
| `--notes` | 备注（可选） |

写入前会结合**历史持仓**校验这笔交易：卖出数量不得超过当时的持有量，数量、单价、费用不得为负。
补录往日交易也按交易发生时的持仓判定，不按当前持仓。校验失败返回退出码 `5`，账本不会写入。

### 3. `holdings list` —— 查看持仓

```bash
# 查看全部持仓
holdings list

# 按盈亏率降序
holdings list --sort 盈亏率

# 只看某个组合
holdings list --group 养老金
```

`--sort` 接受表格里的中文表头（`代码` / `名称` / `市场` / `类型` / `数量` / `成本价` /
`现价` / `市值` / `累计费用` / `盈亏` / `盈亏率`），一律降序；也接受对应的英文列名（如 `profit_rate`）。
传其它值会直接报错，不会静默按原顺序输出。没有行情的标的排在末尾，不会混进排序结果。

**终端窄于 100 列时自动改用简表。** 持仓表有 11 列，在 80 列终端里放不下，
Rich 会平均截断每一列，代码列只剩 `6005…`——认不出持的是什么。所以窄终端下
只显示四列，宽终端（≥ 100 列）显示全部十列：

```text
# 窄终端（80 列）
┌────────┬───────────┬───────────┬─────────┐
│ 代码   │ 数量       │ 现价       │ 盈亏率  │
├────────┼───────────┼───────────┼─────────┤
│ 600519 │  100.0000 │ 1750.0000 │   4.13% │
└────────┴───────────┴───────────┴─────────┘
```

**没同步过时看到的是 `—`，不是亏损。** 还没执行过 `holdings sync` 的标的没有行情，
市值、盈亏、盈亏率一律显示 `—`（现价本来就取不到，同样是 `—`），并在表尾给出提示：

```text
总市值 200.00 | 总成本 100.00 | 总盈亏 100.00 (100.00%) | 累计费用 0.00
1 个标的无行情（成本合计 200.00），未计入上面的汇总；请先执行 holdings sync
```

**外币计价的标的不与人民币混加。** 持有美股（美元报价）与 A 股（人民币报价）时，
汇总只按人民币相加，美元标的的市值、成本、盈亏都不计进去，并在表尾说明：

```text
总市值 1,200.00 | 总成本 1,000.00 | 总盈亏 200.00 (20.00%) | 累计费用 0.00
1 个标的以美元计价（成本合计 1,000.00），未计入上面的汇总；本工具按人民币口径汇总，不做汇率换算
```

行内同理：**账本事实照常显示**（数量、成本价、累计费用），**行情推出来的数字显示 `—`**
（市值、盈亏、盈亏率）——那三个数只有和人民币放在一起才有意义，而它们放不到一起。
现价照常显示，但会带上币种（`200.0000 USD`）：同一列里混着两种货币而不加标注，
用户看到的仍是一个没有单位的数。本工具**不做汇率换算**，要人民币口径的总额，
得自己换算成本币再录入。

汇总的口径是**能按人民币计价的标的**，即「有行情」且「行情是人民币」两者都满足：
没行情的市值算不出来，让它以 0 参与汇总就会把「不知道」印成「血亏 100%」。
没被计入的部分由提示行说明数量与成本合计——两条提示语分别对应两种原因，
要去 sync 的只有前者。

### 4. `holdings meta` —— 维护标的的基础信息

```bash
# 记下名称与年化管理费率（如基金托管费）
holdings meta --symbol 518880 --name "黄金ETF" --fee-rate 0.5

# 看这个标的现在记了什么
holdings meta --symbol 518880

# 删掉
holdings meta --symbol 518880 --remove
```

| 参数 | 说明 |
|------|------|
| `--symbol` | 标的代码（必填） |
| `--name` | 名称，`holdings list` 的名称列取自这里 |
| `--currency` | 币种，默认 `CNY` |
| `--fee-rate` | 年化管理费率（%），**仅作参考展示** |
| `--remove` | 删除该标的的基础信息 |

一个字段都不给时是**查看**当前记录，不会写一条空记录把已有内容清掉。
重复 `--symbol` 是覆盖：没给的字段保留原值。

> ⚠️ **年化管理费率不参与成本计算。** 它只是「你填的费率加起来是多少」，
> 真实费用仍要靠 `holdings add --fee` 逐笔记录。本工具**不会**按持仓天数
> 自动计提管理费——那会让成本价随日历漂移，与移动加权平均成本法冲突。

`AssetType` 的 `etf` 目前没有单独的录入入口，黄金 ETF 用 `--market A股` 记即可。

### 5. `holdings import` —— 对账单批量导入

从券商 / 支付宝导出的对账单批量导入历史交易。

```bash
holdings import --file trades.csv --group 养老金 --fee-column 手续费
```

| 参数 | 说明 |
|------|------|
| `--file` | 对账单文件路径 |
| `--group` | 组合分组（如「养老金」「压岁钱」） |
| `--broker` | 对账单格式名（见下表）；不给则按表头自动识别 |
| `--fee-column` | 文件里的费用列名，覆盖该格式自带的费用列 |
| `--strict` | 有未入账的行时一笔都不写，并以退出码 5 结束 |

导入是**整批校验、单事务写入**：任一行数据非法（或缺少必需列、`--fee-column`
指向不存在的列）则一笔都不写入，并提示出错行号。不会留下半批数据。

#### 支持哪些格式

`--broker` 指定格式名；不给就**按表头自动识别**：

| `--broker` | 格式 | 表头长什么样 |
|-----------|------|-------------|
| `csv` | 标准 CSV（本文档用的那种） | 英文列名 `symbol` / `trade_date` / `trade_type` / … |
| `demo-a` | 示例格式 A | `证券代码` / `成交日期` / `业务名称`；费用拆成 `佣金` + `印花税` + `过户费` 三列 |
| `demo-b` | 示例格式 B | `股票代码` / `发生日期` / `业务标志`；费用一列 `手续费` |

> `demo-a` / `demo-b` 是**演示用的夹具，不是真实券商**。真实对账单各家差别很大，
> 对着想象的格式写映射等于闭着眼猜，所以真实券商的解析器等真实样本
> （BACKLOG B-30）。要接自己的券商：照 `src/holdings/data/brokers/demo_a.py`
> 加一个模块、在 `BROKERS` 里加一行即可，命令行的代码一行都不用改。

**编码不用先转**：UTF-8（含 BOM）、GB18030 / GBK、UTF-16 都直接读。
Windows 上 Excel「另存为 CSV」出来的就是 GBK。

**认不出就不猜**：表头对不上任何格式时报「认不出这份对账单的格式，请用
`--broker` 指定」并列出可选项，**一笔都不写**；同时像两家时同样报错。
每次导入都会印一行「解析格式：…」，告诉你它认成了哪家——认错了才有得查。

#### 哪些行会入账

`trade_type` 列只认这三种值：

| 取值 | 含义 |
|------|------|
| `BUY` | 买入，费用摊入持仓成本 |
| `SELL` | 卖出，数量减少、成本价不变 |
| `FEE` | 独立费用记录，不改变数量与成本 |

#### 哪些行不会入账

一份真实的对账单里还有分红、送转、配股这类行。**它们不入账，但会被逐行报出来**，
不会静默跳过：

```text
解析格式：标准 CSV
识别 6 行，入账 1 笔，未入账 5 行
  第 3 行 分红派息，未入账：分红如何摊销成本尚未支持（见 BACKLOG B-23）
  第 4 行 送股转增，未入账：送股/转增同时改变数量与成本价，口径尚未支持（见 BACKLOG B-23）
  第 5 行 配股，未入账：配股缴款的口径尚未支持（见 BACKLOG B-23）
  第 6 行 银证转账，未入账：银证转账动的是现金，不影响持仓
  第 7 行 利息，未入账：利息不计入持仓成本
```

| 类别 | 常见写法（写到 `trade_type` 列里） | 为什么不入账 |
|------|-----------------------------------|-------------|
| 分红派息 | `分红`、`股息`、`红利入账`、`派息` | 分红如何摊销成本尚无口径（BACKLOG B-23） |
| 送股转增 | `送股`、`转增`、`送转股` | 送转当天数量与成本价同时变，尚无口径（BACKLOG B-23） |
| 配股 | `配股`、`配股缴款` | 缴款口径尚未支持（BACKLOG B-23） |
| 银证转账 | `银行转证券`、`证券转银行` | 动的是现金，不影响持仓 |
| 利息 | `利息`、`利息归本`、`结息` | 不计入持仓成本 |

汇总行固定三段：**识别 / 入账 / 未入账**。未入账是 `0` 也照印——
「0」是被数出来的，不是没数。

这几类行会影响成本价（送转当天尤其），所以工具宁可逐行报出来让你知道少了什么，
也不给一个看着像「全导进来了」的结果。数量与价格列留空即可，不会因此报错。

`--strict` 给脚本用：有未入账的行时**一笔都不写**、退出码 `5`（默认是 `0`）。
之所以是「一笔都不写」而不是「先写进去再报错」，是因为导入目前还没有幂等
（BACKLOG B-29）——写了一半又以非零退出码结束，重跑一次就把账翻倍了。

> `trade_type` 里出现**认不出**的值（既不是上面三种，也不在这张表里）仍然是
> 整批拒绝、退出码 `5`、一笔都不写。那与「认识但不入账」是两回事：
> 前者要你改文件，后者只要你知情。

### 6. `holdings sync` —— 同步最新价格

```bash
holdings sync --market 全部     # 也可指定 A股 / 美股 / 黄金
```

同步会更新 `price_cache` 与持仓市值。同一标的 5 分钟内不会重复请求网络。

只要有一个标的同步成功即返回退出码 `0`；**全部失败返回 `1`**，便于脚本判断。

### 7. `holdings report` —— 生成综合报表

```bash
holdings report --verbose
```

终端显示持仓表格、汇总行与绩效行；加 `--verbose` 额外显示费用分项表与资产配置占比表。

用 `holdings meta --fee-rate` 记过年化管理费率时，多印一行：

```text
年化管理费率合计 0.5%（仅供参考，未计入成本）
```

**它不在「累计费用」里**，也不影响成本价与盈亏——那行字就是为了避免被读成
「费用又多了这么多」。

绩效行取自 `snapshots` 表（与持仓汇总的交易流水是两条数据源），形如：

```text
绩效（4 条快照，2025-01-01 ~ 2025-04-01）：最大回撤 25.00% | 年化收益 47.23% | 夏普 0.94
```

**看到 `—` 不是出错，是这组快照算不出那个指标**，行尾会跟上原因：

| 指标 | 什么时候是 `—` |
|------|---------------|
| 最大回撤 | 快照少于 2 条（1 个点算出的「0.00%」不是结论） |
| 年化收益 | 首末快照跨度不足 30 天，或首条快照净值为 0 |
| 夏普 | 快照间隔不规律。夏普要乘一个年化系数，而该系数只在采样频率恒定时才有意义；快照由你手记，间隔忽长忽短（例如漏记了一周）时强行折算等于给一个错的数 |

间隔的判据是各段间隔的变异系数不超过 25%：月度快照的 28~31 天、每周快照的 7 天都在阈值内。

### 8. `holdings snapshot` —— 记录资产快照

```bash
holdings snapshot --total 158000 --equity 120000 --gold 20000 --cash 18000
```

| 参数 | 说明 |
|------|------|
| `--total` | 总资产（必填） |
| `--equity` | 权益类资产，默认 0 |
| `--gold` | 黄金资产，默认 0 |
| `--cash` | 现金余额，默认 0 |
| `--date` | 快照日期 `YYYY-MM-DD`，默认今天 |
| `--note` | 备注，写入数据库，可用 `holdings snapshots` 查看 |

同日期的快照只能有一条，重复记录会报错（退出码 `4`）。

### 9. `holdings snapshots` —— 查看已记录的快照

```bash
holdings snapshots
```

按日期升序列出全部快照：日期、总资产、权益 / 黄金 / 现金分项，以及备注。

```text
                      资产快照
┌────────────┬────────────┬───────────┬─────────┬──────────┬──────────────────┐
│ 日期       │ 总资产      │ 权益       │ 黄金     │ 现金      │ 备注             │
├────────────┼────────────┼───────────┼─────────┼──────────┼──────────────────┤
│ 2025-01-01 │ 158,000.00 │ 120,000.00 │ 20,000.00 │ 18,000.00 │ 月度定投第12期   │
└────────────┴────────────┴───────────┴─────────┴──────────┴──────────────────┘
```

没记过任何快照时会给出提示，而不是印一张空表。

> 与 `holdings snapshot`（单数）是一对：那个写，这个看。

### 10. `holdings chart` —— 生成净值曲线图

```bash
holdings chart --output networth.html
```

基于 `snapshots` 表生成交互式 HTML 并自动打开浏览器。

| 参数 | 说明 |
|------|------|
| `--output` | 输出 HTML 路径，默认 `networth.html` |
| `--start` | 起始日期 `YYYY-MM-DD`，只画该日（含）之后的点 |

```bash
# 只看 2025 年 3 月以来的净值
holdings chart --start 2025-03-01 --output 2025.html
```

**起始日期之后没有数据时会报错，而不是生成一张空图**——空图与「净值跌没了」
在图上是分不出来的。提示里会带上现有的数据范围，照着调 `--start` 即可：

```text
错误（2）：2030-01-01 之后没有快照（现有 4 条，2025-01-01 ~ 2025-04-01）；
请调整 --start 或先执行 holdings snapshot
```

还没记过任何快照时同理，提示会直接让你先执行 `holdings snapshot`。

### 11. `holdings remove` —— 删除交易

```bash
holdings remove --id 3
```

需二次确认后删除指定 ID 的交易记录。ID 不存在时输出 `错误（2）：未找到交易 #N`
并返回退出码 `2`；用户在确认提示里选「否」或按 `Ctrl-C` 中止，退出码为 `130`。

### 12. `holdings tui` —— 终端界面

```bash
pip install 'holdings[tui]'    # 需要 Textual，默认不装
holdings tui
```

持仓与报表两屏，数据与 CLI 完全同源（都来自 `services/`）。`q` 退出，`r` 刷新。

| 界面元素 | 说明 |
|---------|------|
| 持仓页 | 持仓表 + 汇总行；没同步过的标的显示 `—` 并提示去 `sync`，外币标的按第 3 节的规则排除并提示 |
| 报表页 | 绩效指标（最大回撤 / 年化 / 夏普），口径与 `holdings report` 一致 |

> 界面与 CLI 是**平级的入口**（还有第 13 节的 `holdings web`），各自演进、
> 共用同一套服务层。缺 Textual 时报 `错误（6）：…` 并给出安装命令。

### 13. `holdings web` —— 只读看板

```bash
pip install 'holdings[web]'    # 需要 FastAPI，默认不装
holdings web
# 看板已起在 http://127.0.0.1:8420/
```

持仓 / 报表 / 净值曲线三页，数据与 CLI、TUI 完全同源（都来自 `services/`）。

| 页面 | 内容 |
|------|------|
| `/`（持仓） | 总市值 / 总成本 / 总盈亏 / 累计费用四张卡片 + 持仓表；没同步过的标的显示 `—` 并提示去 `sync`，外币标的按第 3 节的规则排除并提示 |
| `/report`（报表） | 绩效指标（最大回撤 / 年化 / 夏普）+ 资产配置占比 + 费用分项，即 `holdings report --verbose` 的那一份 |
| `/chart`（净值曲线） | 交互式净值曲线，可用起始日期筛；等同于 `holdings chart` 的图 |

```bash
holdings web --host 0.0.0.0 --port 9000    # 改监听地址与端口
```

> **默认只绑 `127.0.0.1`**：这是个把全部持仓摊开的页面。要让局域网里的别的设备
> 也能看，才显式传 `--host 0.0.0.0`——那一刻起它就不再只是本机的事了。
>
> **这一版只读**，页面上没有任何写入入口：`add` / `meta` 要等写入闸门能把
> 校验结果一起搬进页面才做。缺 FastAPI 时报 `错误（6）：…` 并给出安装命令。
>
> 净值曲线那一页从 CDN 取 plotly.js，看它需要联网；要一张能离线打开的图，

### 14. `holdings check` —— 检查运行环境

```bash
holdings check
holdings check --json
```

列出各依赖包是否已安装，标出缺失的必需依赖。全部齐全返回 `0`，
缺失必需依赖返回 `6`（缺少依赖是「装包」问题，与网络故障分开）。

> `--json` 模式的退出码与文本模式一致（缺必需依赖时 `6`），JSON 里也带
> `"ok"` 字段（缺必需依赖时为 `false`），管道消费时用哪个都行。

## 退出码

| 退出码 | 含义 |
|--------|------|
| `0` | 成功 |
| `1` | 网络错误 / 数据源不可用（可重试） |
| `2` | 数据不存在（标的 / 交易记录未找到） |
| `3` | 配置错误 |
| `4` | 数据库错误 |
| `5` | 参数校验失败 / 用户输入非法 |
| `6` | 缺少依赖（重试没有用，要装包） |
| `130` | 用户中止（`Ctrl-C` 或拒绝确认） |

错误信息一律输出到 `stderr`，格式为 `错误（<退出码>）：<人类可读信息>`。
完整规范见 [ERROR_HANDLING.md](ERROR_HANDLING.md)。
