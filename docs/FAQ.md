# 常见问题（FAQ）

## 数据同步

### Q：akshare 报错 `ConnectionError` 怎么办？

A：这是网络或数据源波动导致的。A 股会按 `sync.retry_count` 重试（默认 1 次），失败后降级至 yfinance；若彻底失败会以退出码 `1` 提示「数据源不可用」。可检查网络后重试。

**读那句话的后半截**：彻底失败时消息末尾会带上底层异常，形如
`错误（1）：A股数据源不可用：600519；底层错误：ConnectionError: Remote end closed connection`。
这半截才是能拿来判断的东西——

- `ConnectionError` / `TimeoutError` / 带 `Proxy` 字样的：网络或代理，查网络（含系统代理设置）；
- `未安装 akshare` 这类**不带类型名**的：我们自己抛的、已经说清楚的原因，照着做就行；
- `TypeError` / `AttributeError` / `KeyError`：**这不是网络问题，是我们代码或上游接口的问题**
  （[B-36](BACKLOG.md#b-36) 的 `GC=F` 就是这样——一个签名写错，报出来却像「数据源挂了」，
  用户去重装了 yfinance）。带着这半句话提 issue 能省一大圈。

> **可调项**：`sync.retry_count`（每个数据源各自的重试次数）、
> `sync.timeout_seconds`（每个标的的等待上限，`0` 表示不限）、
> `cache_ttl_seconds`（缓存有效期）、`data_sources.priority`（各市场按什么顺序
> 尝试数据源）均已生效。唯一例外是黄金——它的两个源是两种不同的标的，
> 由代码选路，配置里的 `黄金:` 一项会被忽略（见 [CONFIG_SPEC](CONFIG_SPEC.md)）。

### Q：同一标的多久同步一次价格？

A：默认 5 分钟内同一标的直接返回本地缓存，不重复请求，防止被封禁。可通过 `cache_ttl_seconds` 调整。

## 数据与迁移

### Q：如何把数据库迁移到另一台电脑？

A：两条路。**拷文件**：`data/holdings.db` 到新电脑对应目录即可，数据是单文件
SQLite。**走导出**：`holdings export --out ledger.csv`，在新电脑
`holdings import --file ledger.csv`——多一步，但账本是文本，出问题时看得见
「哪几笔不对」（见 [`holdings export`](USER_GUIDE.md#6-holdings-export--导出账本--持仓表--快照)）。

### Q：如何备份我的数据？

A：最小的一份是 `data/holdings.db`（交易与快照）加 `config.yaml`（配置）。
想要一份能读、能查、能进 Excel 的，用 `holdings export`：

```bash
holdings export --out ledger.csv                  # 账本，能导回来
holdings export --what snapshots --out 快照.csv    # 快照
```

**行情不在导出里**：现价 / 市值 / 盈亏是能从数据源重取的缓存，不是账本，
导进新库后那几列为空，`holdings sync` 一次就回来。要备的是补不回来的东西——
交易流水还能从券商重导，手记的快照不能。

## 费用与成本

### Q：手续费 / 佣金怎么记录？

A：买入时在 `add` 中加 `--fee 5.0`，费用会计入持仓成本。CSV 导入时用 `--fee-column` 指定费用列。

### Q：基金托管费 / 管理费怎么记？

A：使用 `trade_type=FEE` 记录：

```bash
holdings add --symbol 518880 --market A股 --type FEE --qty 0 --price 0 --fee 12.5 --notes "4月托管费"
```

FEE 类型不改变持仓数量与成本，仅在报表中单独汇总费用。

### Q：对账单里的分红 / 送股怎么记？

A：分红与送股 / 转增 / 拆股现在**会入账**，但要求对账单那一行给出关键数字：

| 行 | 需要的列 | 说明 |
|----|---------|------|
| 分红派息 | `quantity` = 持股数、`price` = **每股派息** | 公告「每 10 股派 5 元」→ `price` 填 `0.5` |
| 送股转增 | `quantity` = **新增**股数、`price` = 0 | 十送十填送来的那 100 股，不是 200 |

两者都改成本价而不改「你的收益」：分红摊薄持仓成本（总成本减少 `持股数 × 每股派息`，
股数不变），送转是总成本不变、股数增加。这样一来报表的「总盈亏」里自然含分红，
与券商 APP 上看到的成本价也对得上。

代价是**成本价不再等于「你花的钱」**。长期持有、分红累计到把成本价摊成 0 甚至负数
是真实会发生的；成本价照实显示，但盈亏率会给 `—`——分母不为正时那个百分比没有意义。

手工补录同理：

```bash
holdings add --symbol 600519 --market A股 --type DIVIDEND --qty 1000 --price 0.5 --date 2026-07-15
holdings add --symbol 600519 --market A股 --type BONUS_SHARE --qty 1000 --price 0 --date 2026-07-16
```

日期要记在**持仓期间**（这两类都作用在既有持仓上）；清仓之后才到账的分红会被拒绝，
报「账本上没有持仓」。

### Q：对账单里的配股 / 银证转账 / 利息为什么没有导入？

A：这几类行**不入账，但会逐行报出来**，导入结束时你能看到它们在第几行、为什么不入账：

```text
识别 3 行，入账 1 笔，未入账 2 行
  第 3 行 配股，未入账：配股缴款的口径尚未支持（见 BACKLOG B-38）；可拆成一笔 BUY 手工补录
```

配股要另外缴款、还有配售比例，口径尚未支持（[B-38](BACKLOG.md#b-38)）——可以先拆成
一笔 `BUY` 手工补录；银证转账与利息动的是现金，与持仓无关。它们目前都不进账本——
**不会**被算成「已导入」，也不是被静默丢掉了。

**分红的行如果缺数字，也会落进这一截**，但理由不一样：「对账单这一行没有给出持股数
与每股派息，补上才能入账」——那是让你去补文件，不是让你等新版本。

想让这种情况直接失败（比如写脚本时），加 `--strict`：有未入账的行就一笔都不写、
退出码 5。其余取值认不出的行（既不是上表里的类型，也不在配股 / 银证转账 / 利息这三类里）
一律整批拒绝，需要你先改文件。

### Q：同一份对账单导了两遍，账会翻倍吗？

A：不会。`import` 落库前会查重，发现有已经记过的行就**报出行号、一笔不写**、
退出码 `5`——默认不是静默跳过，因为被跳过的那一笔可能正是你要的：

```text
  第 2 行重复：与库里已有的 #1 是同一笔——600519 2025-01-02 BUY 100 @ 1500
错误（5）：1 行与已有记录重复（第 2 行），未写入任何数据
```

逐月补充导出（本月文件含上月最后几笔）是常事，用 `--dedupe skip` 跳过重复的、
只写新的。判重按券商流水号（标准 CSV 的 `external_id` 列），没有则按
「标的 + 日期 + 类型 + 数量 + 价格 + 费用」的全字段指纹。

> 指纹分不开「同一天分两次、同价同费各买 100 股」这种**真实的两笔成交**，
> 会把它报成重复。确认是两笔就加 `--dedupe off` 原样全写。

### Q：导入报「认不出这份对账单的格式」怎么办？

A：说明表头对不上任何已注册的格式。目前只有标准 CSV（英文列名）与两个
**示例**格式，真实券商的解析器还在等真实样本（[B-30](BACKLOG.md#b-30)）。
工具宁可报错也不猜一个最像的——猜错的代价是整批数字错，而你会以为导成功了。

导入时印的「解析格式：…」会告诉你它认成了哪家；要明写就用 `--broker`
（可选值在报错里列着）。要接自己的券商：照
`src/holdings/data/brokers/demo_a.py` 加一个模块、在注册表里加一行即可，
命令行的代码一行都不用改。格式清单见 [USER_GUIDE](USER_GUIDE.md) 第 5 节。

**编码不用先转**：UTF-8（含 BOM）、GB18030 / GBK、UTF-16 都能直接读，
Windows 上 Excel 另存为出来的 GBK 文件直接导即可。

### Q：卖出的成本怎么算？

A：采用移动加权平均法，卖出时数量减少但成本价保持不变，符合国内多数券商展示逻辑。

## 收益与基准

### Q：`holdings benchmark` 的收益为什么和券商 APP 上的不一样？

A：大概率是**口径不同**，两者其实都不算错。常见的三种：

| 差别 | 这里怎么算 | 券商 APP 常见算法 |
|------|-----------|------------------|
| 出入金 | 从收益里**剔除**（时间加权，TWR）。转入 5 万不算你赚的 | 有的直接按市值涨跌算，入金会被算成收益；有的也做 TWR |
| 分红 | 摊薄持仓成本，盈亏里自然含分红 | 多数是「累计收益」含分红，与这里一致 |
| 区间 | 取你手记的快照那两点之间，间隔由你决定 | 按自然日 / 自然月，或按「持仓成本」算 |

想两者对上，先把**同一段区间、同一笔出入金**摆在一起比。差得离谱时先看
`holdings snapshots` 里那几条的**净入金**记了没有——那是这里唯一需要你手工维护的量。

### Q：为什么我入了一笔钱，收益却显示 0%？

A：这正是要的结果。`holdings benchmark` 算的是**时间加权收益**：市场没动、
只是你转进去 5 万，组合的价值从 10 万变成 15 万，但**你没有跑赢任何东西**。
不剔除这笔钱的话，它会显示成「+50%」，看着像跑赢了大盘——那是个错数。

所以每次往证券账户里转钱（银证转账），记快照时顺手加 `--flow`：

```bash
holdings snapshot --total 150000 --equity 120000 --cash 30000 --flow 50000 --note "追加投入"
```

转进来是正数、转出去是负数。**没记 `--flow` 就等于断言「这段时间没有出入金」**——
真转了钱而没记，那笔钱会被算成你的收益。这一条每次跑都会印在口径句里。

### Q：`--against` 能不能填某只股票或 ETF？

A：**A 股不能**，美股可以。

- A 股走的是 akshare 的**指数**端点，所以 `--against 000001` 是**上证指数**、
  不是平安银行；个股与 ETF 不在这一侧服务。
- 美股走 yfinance，指数（`^GSPC`）与个股 / ETF（`SPY`、`AAPL`）都行。

内置别名有 `沪深300` / `中证500` / `上证指数` / `标普500` / `纳斯达克`，
也可以直接写 6 位 A 股指数代码。**认不出的写法会报错（退出码 `2`）而不是
随便挑个市场去问**——后者的报错会长得像「网络取不到」，把你引到错的方向。

### Q：为什么不给年化收益？

A：年化在两个快照靠得近时会外推出天文数字（`holdings report` 因此要求跨度
≥ 30 天，不够就给 `—`）。而基准对比里组合与基准走的是**同一条快照链**，
间隔不规律不影响两者的可比性，所以直接比区间收益就够了。

## 市场与标的

### Q：支持哪些市场？

A：A 股、美股、黄金。黄金**由代码选路**：写国内现货 / 黄金 ETF 的代码（如 `518880`）
走 A 股链路，写 `GC=F` 取国际金价（美元/盎司）。两者不是彼此的备份，拉不到就是拉不到，
**不会**互相顶替——详见 [配置项字典](CONFIG_SPEC.md) 里对 `data_sources.priority` 的说明。

### Q：找不到我的标的怎么办？

A：检查代码与市场是否匹配，程序会以退出码 `2` 提示「未找到该标的」。若仍无法识别，可在 `data/` 层扩展对应数据源。

A：不支持。本工具只做记账与追踪，不接券商下单接口。
